## Зачем нужно

Тема регулярно встречается на backend-интервью: сильный ответ связывает механизм с наблюдаемым поведением, отказами и production-решением.

## Как работает

Schema validator отклоняет неизвестные/неверные поля до handler, нормализует только явно разрешённые значения. Синтаксическая ошибка даёт 400; корректная форма, нарушающая состояние ресурса, обычно 409 или 422 по контракту.

## Что спрашивают

- Как работает HTTP validation на практике?
- Какой типичный failure mode связан с HTTP validation?
- Какие trade-offs важно назвать для HTTP validation?

## Ответы

### Как работает HTTP validation на практике?

Schema validator отклоняет неизвестные/неверные поля до handler, нормализует только явно разрешённые значения. Синтаксическая ошибка даёт 400; корректная форма, нарушающая состояние ресурса, обычно 409 или 422 по контракту.

### Какой типичный failure mode связан с HTTP validation?

Автоматическое coercion превращает неожиданные строки в числа/boolean; отсутствие лимитов допускает огромные arrays и regex DoS. Проверка уникальности только до insert имеет race — constraint БД остаётся обязательным.

### Какие trade-offs важно назвать для HTTP validation?

На boundary применяют allowlist, ограничения длины/диапазона и единый error format. Доменные инварианты проверяет domain/use case, а БД обеспечивает конкурентные constraints.
