---
title: Auth (gateway)
summary: Auth на API Gateway — проверка identity/токена на входе, дальше часто передают user context внутренним сервисам.
---

## Для чего

Чтобы не дублировать JWT-валидацию в каждом сервисе и единообразно отсекать анонимов.

## Пример

Gateway проверяет Bearer/cookie → при успехе прокидывает `X-User-Id` / signed claims в Orders. Без токена — `401` у края.

## Примечание

Внутренние сервисы всё равно должны mistrust'ить сырые заголовки с интернета (mTLS/mesh, сеть только через gateway). Authorization по ролям может остаться в сервисах.
