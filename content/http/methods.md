## Зачем нужно

Тема регулярно встречается на backend-интервью: сильный ответ связывает механизм с наблюдаемым поведением, отказами и production-решением.

## Как работает

GET/HEAD безопасны и идемпотентны; PUT и DELETE идемпотентны по ожидаемому состоянию; POST обычно нет; PATCH зависит от patch format. OPTIONS описывает возможности, HEAD возвращает headers без body.

## Что спрашивают

- Как работает HTTP methods на практике?
- Какой типичный failure mode связан с HTTP methods?
- Какие trade-offs важно назвать для HTTP methods?

## Ответы

### Как работает HTTP methods на практике?

GET/HEAD безопасны и идемпотентны; PUT и DELETE идемпотентны по ожидаемому состоянию; POST обычно нет; PATCH зависит от patch format. OPTIONS описывает возможности, HEAD возвращает headers без body.

### Какой типичный failure mode связан с HTTP methods?

GET с side effect может быть вызван crawler/prefetch, а повтор POST после timeout создаёт дубль. PUT, который генерирует новый ID при каждом повторе, нарушает заявленную идемпотентность.

### Какие trade-offs важно назвать для HTTP methods?

POST создаёт подчинённый ресурс/команду, PUT заменяет ресурс по известному URI, PATCH частично меняет. Семантика важнее CRUD-догмы; сервер возвращает 405 и `Allow` для неподдерживаемого метода.
