---
title: Generic functions
summary: Generic-функция с `<T>` связывает типы входа и выхода так, чтобы сохранялась конкретика аргумента, а не только `unknown`/`any`.
---

## Для чего

Чтобы писать переиспользуемые функции (`identity`, `map`, `pick`) без потери типа: что передали — то и вернули/вывели.

## Пример

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}

const n = first([1, 2]);     // number | undefined
const s = first(["a", "b"]); // string | undefined
```

## Примечание

Часто `T` выводится из аргументов — явно писать `first<number>(…)` не нужно. Constraints: `T extends { id: string }` ограничивают, что можно передать.

## Вопросы и ответы

### Зачем generics, если можно поставить `any`?

`any` отключает проверку. Generic сохраняет связь типов и ловит ошибки в вызывающем коде.

### Что такое type argument inference?

TS сам подставляет `T` из переданных аргументов. Явный `<T>` нужен, когда вывести нельзя или хотите зафиксировать тип.

### Чем generic-функция отличается от generic-типа?

У функции параметр типа живёт на вызове (`fn<T>(…)`). У типа/интерфейса — при использовании типа (`Repo<T>`, `Array<T>`). Идея та же: параметр вместо конкретного типа.
