---
title: Readonly
summary: `readonly` запрещает присваивание полю или элементу на уровне типов; в runtime объект всё ещё можно мутировать.
---

## Для чего

Чтобы зафиксировать намерение «не менять» в API и пропсах и поймать случайные присваивания на compile-time.

## Пример

```ts
type User = {
  readonly id: string;
  name: string;
};

const u: User = { id: "1", name: "Ada" };
// u.id = "2"; // ошибка
```

## Примечание

`Readonly<T>` и `readonly T[]` — поверхностные: вложенные объекты не становятся readonly автоматически. Глубокая неизменяемость — отдельный тип или `as const` / runtime freeze.

## Вопросы и ответы

### Защищает ли `readonly` в runtime?

Нет. Это только проверка TypeScript. `Object.freeze` — уже runtime, и то неглубокий без рекурсии.

### Чем `readonly T[]` отличается от `ReadonlyArray<T>`?

По сути одно и то же: нет `push`/`splice` и записи по индексу на уровне типов.

### Можно ли присвоить `readonly` массив обычному `T[]`?

Нет (в строгих проверках): иначе через мутабельную ссылку сломали бы контракт readonly.
