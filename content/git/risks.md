## Для чего

Чтобы PR оценивали по вероятности вреда, а не только по стилю кода.

## Пример

«Меняете кэш ключей — возможен stampede». «Убрали lazy с hero — ок для LCP, следите за вес». «Нет теста на пустой список».

## Примечание

Назовите риск + как проверить/откатить. Молчаливый approve без чтения — тоже риск команды.
