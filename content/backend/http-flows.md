---
title: HTTP flows
summary: HTTP flow в E2E — цепочка запросов как у пользователя: создать → прочитать → обновить → ошибочный шаг.
---

## Для чего

Чтобы поймать поломки на стыках эндпоинтов, которые одиночный API-тест не видит.

## Пример

Register → login → `POST /orders` → `GET /orders/:id` → ожидаемые статусы и данные сквозь шаги.

## Примечание

Держите сценарий коротким и бизнес-значимым. Гигантский E2E на всё — медленный и хрупкий.
