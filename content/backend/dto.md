## Зачем нужно

Тема регулярно встречается на backend-интервью: сильный ответ связывает механизм с наблюдаемым поведением, отказами и production-решением.

## Как работает

Входной DTO парсится и валидируется до use case, затем явно преобразуется в command/domain value objects. Выходной DTO фиксирует публичный контракт и не позволяет случайно сериализовать внутренние поля entity.

## Ответы

### Как работает DTO на практике?

Входной DTO парсится и валидируется до use case, затем явно преобразуется в command/domain value objects. Выходной DTO фиксирует публичный контракт и не позволяет случайно сериализовать внутренние поля entity.

### Какой типичный failure mode связан с DTO?

TypeScript type исчезает в runtime, поэтому без schema/decorators непроверенный JSON остаётся `unknown`. Использование ORM entity как response может раскрыть password hash, создать циклическую сериализацию и связать API с миграциями.

### Какие trade-offs важно назвать для DTO?

Отдельный DTO нужен на внешней или нестабильной границе. Внутри одного доверенного модуля лишние копии типов дают шум; mapping должен быть явным там, где различаются семантика, версия или безопасность.
