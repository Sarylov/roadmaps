---
title: N+1 problem
summary: N+1 — антипаттерн: 1 запрос списка + N запросов на каждую связанную сущность вместо одного (или малого числа) join/include.
---

## Для чего

Чтобы не убивать latency и пул соединений «невидимыми» запросами в цикле.

## Пример

100 заказов → `find orders`, затем в цикле `find user` = 101 запрос.  
Правильно: `include: { user: true }` / один JOIN / DataLoader.

## Примечание

Часто всплывает с lazy relations в ORM и GraphQL без dataloader. Ловят профилированием SQL-логов и `EXPLAIN`, не «на глаз по коду сервиса».
