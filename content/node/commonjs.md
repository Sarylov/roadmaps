## Зачем нужно

Тема регулярно встречается на backend-интервью: сильный ответ связывает механизм с наблюдаемым поведением, отказами и production-решением.

## Как работает

`require()` синхронно разрешает и выполняет модуль при первом обращении, затем возвращает объект из `require.cache`. Код оборачивается функцией, поэтому доступны `module`, `exports`, `__dirname`; циклический импорт видит частично заполненный export.

## Ответы

### Как работает CommonJS на практике?

`require()` синхронно разрешает и выполняет модуль при первом обращении, затем возвращает объект из `require.cache`. Код оборачивается функцией, поэтому доступны `module`, `exports`, `__dirname`; циклический импорт видит частично заполненный export.

### Какой типичный failure mode связан с CommonJS?

`exports = value` не меняет `module.exports`, а только локальную ссылку. Скрытое singleton-состояние сохраняется в cache и осложняет тесты; циклы дают `undefined` в зависимости от порядка выполнения.

### Какие trade-offs важно назвать для CommonJS?

CommonJS практичен для legacy-пакетов и конфигурационных файлов. Для нового переносимого кода предпочтителен ESM; при interop нельзя без проверки предполагать, как CJS namespace отображается на default и named imports.
