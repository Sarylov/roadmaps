## Зачем нужно

Тема регулярно встречается на backend-интервью: сильный ответ связывает механизм с наблюдаемым поведением, отказами и production-решением.

## Как работает

Write path валидирует URL, генерирует Base62 ID и сохраняет mapping; read path делает lookup и отвечает `301` или `302`. При 100 млн ссылок ключ из 7 Base62-символов даёт около 3.5 трлн комбинаций; cache закрывает популярные redirect.

## Ответы

### Как работает URL shortener на практике?

Write path валидирует URL, генерирует Base62 ID и сохраняет mapping; read path делает lookup и отвечает `301` или `302`. При 100 млн ссылок ключ из 7 Base62-символов даёт около 3.5 трлн комбинаций; cache закрывает популярные redirect.

### Какой типичный failure mode связан с URL shortener?

Случайные ключи требуют обработки collision, последовательные раскрывают объём и позволяют enumeration. Популярная ссылка создаёт hot key, а открытый сервис становится phishing redirect; нужны rate limits и reputation checks.

### Какие trade-offs важно назвать для URL shortener?

`301` лучше кэшируется, но мешает изменить destination; `302/307` сохраняляет контроль и аналитику ценой запроса к сервису. ID service даёт уникальность, random keys проще распределять между writers.
