title: Keys в React
summary: `key` задаёт стабильную идентичность соседних React-элементов и помогает reconciliation правильно сохранить DOM и состояние при изменении списка.
---

## Зачем нужно

Ошибочный `key` вызывает трудноуловимые баги: состояние формы переезжает в другую строку, анимация ломается, компонент неожиданно монтируется заново.

## Как работает

React сравнивает детей одного родителя по паре `key + type`. Ключ должен быть уникальным среди соседей, стабильным между рендерами и полученным из данных, например `todo.id`. Он не передаётся компоненту как обычный prop.

Индекс допустим только для действительно статичного списка, который не сортируется, не фильтруется и не меняется в середине. `Math.random()` и новые UUID на каждом рендере заставляют React пересоздавать все элементы. Осознанная смена `key`, наоборот, полезна для сброса состояния, например формы при выборе другого пользователя.

## Что спрашивают

- Почему индекс массива часто плохой `key`?
- Должен ли `key` быть глобально уникальным?
- Как с помощью `key` сбросить состояние компонента?

## Ответы

### Почему индекс массива часто плохой `key`?

После вставки, удаления или сортировки индекс начинает обозначать другую сущность. React сохраняет Fiber и локальное состояние по позиции, поэтому значение input или фокус может оказаться у другой строки.

### Должен ли `key` быть глобально уникальным?

Нет. Достаточно уникальности среди непосредственных соседей одного массива. Один и тот же идентификатор можно использовать в независимых списках.

### Как с помощью `key` сбросить состояние компонента?

Нужно изменить ключ на границе компонента: `<Profile key={userId} />`. Для React это другая идентичность, поэтому старое поддерево размонтируется, а новое получит начальное состояние.
