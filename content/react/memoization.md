## Зачем нужно

Хуки мемоизации помогают пропустить дорогое вычисление или сохранить identity для memoized child/effect, но не исправляют логику и имеют собственную стоимость.

## Как работает

`useMemo(() => compute(a), [a])` повторяет вычисление при изменении `a`. `useCallback(fn, deps)` эквивалентен мемоизации самой функции. Массив зависимостей должен включать все reactive values из замыкания; пропуск даёт stale closure.

React может отбросить кеш, поэтому код обязан оставаться корректным без него. Сначала измеряют Profiler, затем мемоизируют узкое место. Часто проще убрать лишний effect, передать примитив или переместить объект внутрь вычисления.

## Что спрашивают

- Чем `useMemo` отличается от `useCallback`?
- Можно ли использовать `useMemo` для корректности?
- Что произойдёт при неполных зависимостях?

## Ответы

### Чем `useMemo` отличается от `useCallback`?

Первый кеширует возвращённое значение, второй — функцию. Оба сравнивают dependency list и являются performance optimization.

### Можно ли использовать `useMemo` для корректности?

Нет. React не обещает вечное хранение кеша. Если повторное вычисление ломает поведение, нужен state, ref или исправление побочного эффекта.

### Что произойдёт при неполных зависимостях?

Кеш или callback продолжит использовать значения старого рендера. Это логический баг, который должен обнаруживать hooks linter.
