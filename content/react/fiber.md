## Зачем нужно

Fiber объясняет concurrent rendering, прерываемую render phase и различие между вычислением нового UI и его атомарным применением.

## Как работает

Каждому элементу дерева соответствует Fiber-узел со ссылками на родителя, ребёнка и соседа, props, state и эффектами. React хранит текущее дерево и строит альтернативное `workInProgress` дерево.

Render phase вычисляет изменения и может быть приостановлена, отброшена или начата заново. Обновления распределяются по приоритетам (`lanes`), поэтому срочный ввод не обязан ждать фонового перехода. Commit phase применяет подготовленные DOM-изменения и эффекты синхронно: пользователь не видит частично зафиксированное дерево.

Fiber — внутренняя реализация, а не API приложения; опираться на поля Fiber нельзя.

## Что спрашивают

- Зачем React понадобился Fiber?
- Чем render phase отличается от commit phase?
- Означает ли concurrent rendering параллельное выполнение JavaScript?

## Ответы

### Зачем React понадобился Fiber?

Старый рекурсивный reconciler выполнял работу одним непрерывным стеком. Fiber представляет её как отдельные единицы, которым можно назначать приоритет, откладывать их и продолжать позже.

### Чем render phase отличается от commit phase?

Render phase строит новое дерево и рассчитывает эффекты; она должна оставаться чистой и может повторяться. Commit phase меняет DOM, вызывает layout effects и не прерывается посередине.

### Означает ли concurrent rendering параллельное выполнение JavaScript?

Нет. Обычно работа остаётся на main thread, но React кооперативно планирует её, уступая браузеру и переключаясь между приоритетами. Это конкурентность по планированию, не обязательный multithreading.
