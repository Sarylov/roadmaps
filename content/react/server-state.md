title: Server state
summary: Server state — удалённые данные, которыми владеет сервер; клиент хранит лишь кеш с правилами свежести, повторной загрузки и синхронизации.
---

## Зачем нужно

Серверные данные асинхронны, могут устареть и измениться другим клиентом. Простого `useState` недостаточно для deduplication, retry, cache invalidation и гонок запросов.

## Как работает

Кеш запроса индексируется стабильным query key, например `['user', id]`. Библиотека server-state загружает данные, объединяет одинаковые запросы, сообщает состояния pending/error/success и решает, когда данные стали stale.

После mutation кеш либо инвалидируют и перечитывают, либо обновляют напрямую; optimistic update требует snapshot и rollback. Отмена или игнорирование устаревшего ответа предотвращает race condition. Server state не следует копировать в глобальный client store без причины: это создаёт второй кеш и расходящиеся источники истины.

## Что спрашивают

- Чем server state отличается от client state?
- Что такое stale data и invalidation?
- Как безопасно сделать optimistic update?

## Ответы

### Чем server state отличается от client state?

Client state принадлежит интерфейсу: открытая вкладка, черновик, фильтр. Server state принадлежит backend, получается асинхронно, имеет время свежести и может измениться вне текущего приложения.

### Что такое stale data и invalidation?

Stale означает, что кеш можно показать, но по политике он уже требует перепроверки. Invalidation помечает связанные query как устаревшие; это не обязательно немедленное удаление данных.

### Как безопасно сделать optimistic update?

Отменить конфликтующие refetch, сохранить предыдущий кеш, применить ожидаемый результат и отправить mutation. При ошибке восстановить snapshot, а после завершения инвалидировать query для сверки с сервером.
