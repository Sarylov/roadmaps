---
title: React Server Components
summary: React Server Components выполняются только на сервере и передают клиенту сериализованное UI-дерево, уменьшая клиентский JavaScript и приближая чтение данных к источнику.
---

## Зачем нужно

RSC позволяют не отправлять в браузер код тяжёлых зависимостей и безопасно обращаться к серверным ресурсам, сохраняя интерактивность в явных client boundaries.

## Как работает

Server Component выполняется на сервере и может быть `async`, читать БД или filesystem. Его результат кодируется в RSC/Flight payload, из которого React собирает дерево. Он не использует state, effects и browser API.

Файл с `"use client"` задаёт клиентскую границу: сам модуль и его транзитивные импорты попадают в client graph. Server Component может передать Client Component сериализуемые props и `children`, но клиентский модуль не может просто импортировать серверный. RSC не равен SSR: RSC определяет, где выполняется компонент, а SSR превращает начальное дерево в HTML; технологии обычно комбинируются фреймворком.

## Что спрашивают

- Чем RSC отличается от SSR?
- Что означает директива `"use client"`?
- Какие данные можно передавать через server/client boundary?

## Ответы

### Чем RSC отличается от SSR?

SSR генерирует начальный HTML, после чего клиентские компоненты гидратируются. RSC генерирует описание React-дерева и код серверных компонентов никогда не попадает в bundle. RSC может обновлять дерево и после первого HTML.

### Что означает директива `"use client"`?

Она отмечает вход в клиентский module graph, а не отдельную строку выполнения. Все импорты ниже границы должны быть пригодны для браузера; ставить директиву во всех файлах не нужно.

### Какие данные можно передавать через server/client boundary?

Только поддерживаемые сериализуемые значения и специальные серверные ссылки фреймворка. Нельзя передать произвольное замыкание, DOM-узел или экземпляр класса и ожидать сохранения его поведения.
