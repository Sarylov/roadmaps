title: Non-blocking
summary: Non-blocking I/O — операция регистрируется и завершается позже через колбэк/промис, не удерживая поток на ожидании.
---

## Для чего

Чтобы один поток обслуживал много соединений, пока ждёт сеть или диск.

## Пример

```js
fs.readFile('a.txt', (err, data) => {
  // сюда вернёмся позже; сейчас loop свободен
})
```

## Примечание

Non-blocking ≠ параллельный CPU. Тяжёлый sync-код всё равно блокирует loop. Часть fs/DNS/crypto в Node идёт через thread pool libuv.

## Вопросы и ответы

### Что такое non-blocking I/O?

Операция регистрируется и завершается позже через колбэк/промис: поток не сидит в ожидании сети или диска и может обслуживать другие соединения.

### Значит ли non-blocking параллельный CPU?

Нет. Тяжёлый синхронный код всё равно блокирует loop. Non-blocking про ожидание I/O, а не про многоядерный параллелизм JS.

### Кто в Node реально делает часть async I/O?

Часть fs/DNS/crypto идёт через thread pool libuv: с точки зрения JS это колбэк/промис, под капотом — пул потоков.
