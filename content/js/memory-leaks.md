---
title: Memory leaks
summary: Memory leak — когда данные больше не нужны, но на них остаются ссылки, поэтому GC не может их забрать.
---

## Для чего

Чтобы долгоживущий Node-процесс не раздувал память из-за кэшей, слушателей и забытых таймеров.

## Пример

```js
// утечка: слушатель живёт forever
emitter.on('event', handler)
// забыли emitter.off('event', handler)
```

## Примечание

Типичные источники: глобальный кэш без LRU/TTL, незакрытые таймеры, замыкания на большие объекты, подписки. Ловят сравнением heap snapshots.

## Вопросы и ответы

### Что такое memory leak в JS?

Данные уже не нужны, но на них остались ссылки — GC не может их забрать, и память процесса растёт.

### Типичные источники утечек в Node?

Глобальный кэш без LRU/TTL, забытые `on` без `off`, незакрытые таймеры/интервалы, замыкания на большие объекты, висящие подписки.

### Как ловят утечку на практике?

Сравнивают heap snapshots во времени (или clinic/профайлер): ищут объекты, которые только растут и не отпускаются между нагрузками.
