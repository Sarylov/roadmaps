---
title: Garbage collection
summary: Garbage collection — автоматическое освобождение объектов, до которых больше нельзя дойти из корней (roots).
---

## Для чего

Чтобы не освобождать память вручную, но понимать, когда объект «держится» ссылкой и не собирается.

## Пример

```js
let user = { name: 'Ann' }
user = null // объект станет кандидатом на GC, если больше нигде нет ссылок
```

## Примечание

GC недетерминирован: паузы влияют на latency. Частый alloc в hot path даёт churn и лишние паузы.

## Вопросы и ответы

### Как GC решает, что можно собрать?

Объект кандидат на сборку, если до него нельзя дойти из корней (roots): стек, глобальные, активные замыкания. Нет достижимых ссылок — можно забрать.

### Когда освободится память после `obj = null`?

Не сразу: GC недетерминирован. Объект станет кандидатом, если больше нигде нет ссылок; момент очистки неизвестен.

### Почему частые аллокации в hot path плохи?

Churn: много короткоживущих объектов → чаще GC pauses → хуже latency, даже если «утечки» нет.
