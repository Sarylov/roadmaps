title: Modules
summary: Modules — способ разбить код на файлы с явным import/export границ публичного API.
---

## Для чего

Чтобы не сваливать всё в один файл, контролировать зависимости и избегать конфликтов имён в глобальной области.

## Пример

```js
// user.js
export function getUser(id) { /* ... */ }

// app.js
import { getUser } from './user.js'
```

## Примечание

В Node есть ESM (`import`) и CommonJS (`require`). ESM лучше для статического анализа и tree-shaking; смешение систем требует аккуратности (`type: module`, `.cjs`/`.mjs`).

## Вопросы и ответы

### Зачем нужны модули?

Чтобы разбить код на файлы с явным публичным API через `export`/`import`, избежать глобальных имён и явно видеть зависимости.

### Чем ESM отличается от CommonJS?

ESM — статический `import`/`export`, удобен для tree-shaking и анализа. CommonJS — динамический `require`, синхронная загрузка. В Node их смешивают осторожно (`"type": "module"`, `.mjs`/`.cjs`).

### Что экспортирует модуль по умолчанию vs именованно?

`export default` — один «главный» экспорт на файл, импорт без фигурных скобок. Named export — несколько имён, импорт `{ name }` (или `* as ns`).
