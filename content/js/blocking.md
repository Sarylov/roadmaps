---
title: Blocking
summary: Blocking — когда код так долго занимает поток, что другие задачи (запросы, таймеры) ждут.
---

## Для чего

Чтобы не класть тяжёлую синхронщину в горячий путь обработки запроса и понимать, почему «висит» API.

## Пример

```js
// плохо в request handler
const data = fs.readFileSync('huge.json', 'utf8')
JSON.parse(data) // держит event loop
```

## Примечание

В Node один event-loop поток: sync `fs`, огромный `JSON.parse`, тяжёлый CPU блокируют почти всё в процессе. CPU выносят в `worker_threads` или очередь.

## Вопросы и ответы

### Что значит blocking в Node?

Код так долго занимает поток event loop, что другие задачи — запросы, таймеры, I/O-колбэки — ждут и API «висит».

### Какие операции чаще всего блокируют?

Синхронный `fs`, огромный `JSON.parse`, тяжёлый CPU в request handler. Всё, что долго крутится на основном потоке без `await`/колбэка.

### Куда выносить CPU-работу?

В `worker_threads`, отдельный процесс или очередь задач — чтобы не держать event loop на вычислениях.
