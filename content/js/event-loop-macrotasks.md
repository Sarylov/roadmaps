## Для чего

Чтобы объяснять отложенное выполнение и не ждать, что `setTimeout(0)` мгновенно «разгрузит» тяжёлую работу.

## Пример

```js
console.log('sync')
setTimeout(() => console.log('timeout'), 0)
Promise.resolve().then(() => console.log('then'))
// sync → then → timeout
```

## Примечание

`setTimeout(0)` только откладывает колбэк на следующую macrotask. Если сам колбэк тяжёлый — поток снова блокируется. В Node фазы loop другие (libuv), идея та же.

## Вопросы и ответы

### Что такое macrotasks?

Задачи «крупного» цикла: `setTimeout`/`setInterval`, I/O, UI-события. Между ними успевают microtasks и (в браузере) отрисовка.

### Делает ли `setTimeout(0)` работу мгновенной?

Нет: только откладывает колбэк на следующую macrotask после текущего стека и microtasks. Минимальная задержка и очередь другие задачи могут сдвинуть момент.

### Если колбэк таймера тяжёлый — что будет?

Поток снова блокируется на время выполнения: другие macrotasks и обработка I/O ждут, как при любом долгом sync-коде.
