## Зачем нужно

На собесе почти всегда просят объяснить closure на примере и ловят на цикле `for` + `var` / асинхронных колбэках. В коде это паттерн фабрик, memoize, React hooks.

## Как работает

```js
function makeCounter() {
  let n = 0
  return () => ++n
}
const c = makeCounter()
c() // 1
c() // 2
```

Внутренняя функция держит ссылку на окружение (`n`), пока на неё есть ссылки. Не «копия значения на момент создания» для `let`/`const` — живая привязка; для `var` в цикле — одна общая переменная на функцию.

MDN: [Closures](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Closures).

## Что спрашивают

- Чем closure отличается от scope?
- Почему в цикле с `var` и `setTimeout` все логируют одно число?
- Где closures дают утечки памяти?

## Ответы

### Чем closure отличается от scope?

**Scope** — правила видимости имён в момент написания/разбора кода. **Closure** — следствие lexical scope: функция уносит с собой доступ к внешней области и может читать/менять эти привязки после выхода из внешней функции. Scope есть всегда; о closure говорят, когда внутренняя функция «выжила» наружу.

### Почему в цикле с `var` и `setTimeout` все логируют одно число?

`var` function-scoped: одна переменная `i` на весь цикл. К моменту срабатывания таймеров цикл уже закончен → все колбэки видят финальное `i`. С `let` на каждой итерации своя привязка → разные значения. Исправление: `let`, IIFE с параметром, или `.bind`.

### Где closures дают утечки памяти?

Если долгоживущая функция (глобальный хендлер, кэш, подписка) замыкает большой объект/DOM и больше не отпускает ссылку — GC не соберёт эти данные. Типично: забыли `removeEventListener`, модульный синглтон держит огромный массив «на всякий случай».
