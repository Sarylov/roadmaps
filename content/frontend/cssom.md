## Зачем нужно

CSS обычно render-blocking: браузеру нужны стили, прежде чем безопасно показать страницу. Это влияет на FCP/LCP и стратегию доставки critical CSS.

## Как работает

Браузер загружает CSS, токенизирует правила и строит CSSOM. Cascade выбирает победившие декларации, наследование и вычисление значений формируют computed style каждого релевантного элемента. DOM и computed styles дают render tree.

Изменение класса инвалидирует стили для затронутой области; последствия могут ограничиться composite, потребовать repaint или layout. Stylesheet с подходящим `media` может не блокировать текущий рендер, хотя ресурс загружается.

## Что спрашивают

- Почему CSS называют render-blocking ресурсом?
- Чем CSSOM отличается от DOM?
- Что происходит после изменения класса элемента?

## Ответы

### Почему CSS называют render-blocking ресурсом?

Без CSSOM браузер не знает итоговую геометрию и внешний вид и рисковал бы показать flash of unstyled content. Поэтому критические stylesheet задерживают первый render.

### Чем CSSOM отличается от DOM?

DOM моделирует структуру и содержимое документа. CSSOM моделирует правила стилей и предоставляет API для stylesheet; вместе они участвуют в вычислении render tree.

### Что происходит после изменения класса элемента?

Браузер пересчитывает стили затронутых элементов. Если меняется геометрия, следует layout; при изменении пикселей — paint; свойства вроде `transform` уже выделенного слоя могут потребовать только composite.
