## Зачем нужно

Тема регулярно встречается на backend-интервью: сильный ответ связывает механизм с наблюдаемым поведением, отказами и production-решением.

## Как работает

Gateway принимает валидный ID или генерирует новый, приложение хранит его в request context и передаёт в разрешённом header/message metadata. Все логи получают поле `correlation_id`; trace ID лучше переиспользовать как основную связь.

## Ответы

### Как работает Correlation IDs на практике?

Gateway принимает валидный ID или генерирует новый, приложение хранит его в request context и передаёт в разрешённом header/message metadata. Все логи получают поле `correlation_id`; trace ID лучше переиспользовать как основную связь.

### Какой типичный failure mode связан с Correlation IDs?

Слепое доверие пользовательской строке позволяет log injection и огромные значения. Потеря context в async callback разрывает цепочку; создание нового ID в каждом сервисе делает поиск бесполезным.

### Какие trade-offs важно назвать для Correlation IDs?

Correlation ID отвечает «какие события относятся к запросу», trace/span IDs — ещё и «кто кого вызвал и сколько заняло». В публичном API ID валидируют по длине/формату и возвращают клиенту для support.
