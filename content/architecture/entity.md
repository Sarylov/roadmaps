## Зачем нужно

Тема регулярно встречается на backend-интервью: сильный ответ связывает механизм с наблюдаемым поведением, отказами и production-решением.

## Как работает

Order с `orderId` остаётся тем же заказом после смены статуса. Изменение выполняется методом вроде `confirm`, который проверяет допустимый переход; persistence mapper отдельно восстанавливает и сохраняет entity.

## Ответы

### Как работает Entity на практике?

Order с `orderId` остаётся тем же заказом после смены статуса. Изменение выполняется методом вроде `confirm`, который проверяет допустимый переход; persistence mapper отдельно восстанавливает и сохраняет entity.

### Какой типичный failure mode связан с Entity?

Anemic entity с публичными setters позволяет получить невозможное состояние. Сравнение всех полей делает изменённую entity «другой», а использование database row как доменной модели протаскивает nullable/ORM-детали.

### Какие trade-offs важно назвать для Entity?

Entity выбирают, когда жизненный цикл и identity значимы. Если важны только атрибуты и объект взаимозаменяем, это value object; не каждая таблица обязана становиться entity.
